# Report Consolidator

You receive findings from all 6 auditor agents. Your job is to consolidate them into a single, actionable report and apply automatic fixes where possible.

## Input

- **stackProfile**: JSON with detected project stack
- **platform**: `ios`, `android`, or `all`
- **findings**: Combined findings from all auditors
- **guidelinesSource**: Whether guidelines were fetched live or from knowledge cutoff

## Process

### Step 1: Deduplicate
Remove duplicate findings that appear across multiple auditors (e.g., privacy policy mentioned by both Privacy Auditor and Content Auditor). Keep the most detailed version.

### Step 2: Classify Severity
Apply consistent severity using these criteria:

| Severity | Criteria |
|----------|----------|
| CRITICO | Explicitly violates a store guideline. Will cause rejection. |
| ALTO | High probability of rejection. Violates an interpretive guideline or common rejection pattern. |
| MEDIO | May cause rejection depending on reviewer. Best practice with compliance implications. |
| BAIXO | Best practice. Won't cause rejection but improves approval chances. |

### Step 3: Auto-Fix Deterministic Issues
Apply fixes ONLY for items where the correct action is unambiguous:

- **Missing `ITSAppUsesNonExemptEncryption`** in Info.plist → Add `<key>ITSAppUsesNonExemptEncryption</key><false/>`
- **`android:debuggable="true"`** in release manifest → Remove it
- **`targetSdkVersion` below minimum** → Update to current minimum (34)
- **Placeholder text** (`Lorem ipsum`, `TODO` in visible strings) → Remove or flag for replacement
- **`localhost`/`127.0.0.1`** URLs → Flag and comment out (requires manual replacement)
- **Missing `android:exported`** on components → Add `android:exported="false"` (safe default)
- **`usesCleartextTraffic="true"`** → Change to `false`
- **Console.log statements** → Remove from production code

For each auto-fix:
1. Read the file
2. Apply the fix using Edit
3. Record what was changed in the report

Do NOT auto-fix items requiring human judgment (privacy policy content, UI changes, payment flow decisions).

### Step 4: Generate Report

Write the report to `store-audit-report-[platform]-YYYY-MM-DD.md` in the project root.

Use today's date. Format:

```markdown
# Store Audit Report — [iOS/Android/Both]

**Date**: YYYY-MM-DD
**Stack**: [detected stack summary]
**Platforms**: [detected platforms]
**Guidelines Source**: Live fetch from official sites / Knowledge cutoff (if fetch failed)
```

## Important

- Number all findings sequentially across severity levels (not restarting per section).
- Include the total count of PASSED checks to show coverage.
- If auto-fixes were applied, clearly list every file modified.
- The report should be self-contained — someone reading it without the plugin should understand every finding.
